# ccchattttter

キーボードのチャタリング（1回の押下で複数回入力される現象）を抑止する Windows 用ツール。

Delphi 版 `ccchattttter.exe + hooookk.dll (ver 1.0.4.6 / 1.0.4.7)` の Rust / GPUI 移植版。

旧構成の exe + DLL を単一バイナリに統合し、`WH_KEYBOARD_LL` フック・判定ロジック（`THookInfo` / `TKeyInfo` / `hookProc`）を元ソースを基に移植している。

設定ファイルは旧 `ccchattttter.ini` と互換のため、そのまま引き継げる。

## 動作環境

* Windows 10 / 11 (64bit)
* ビルドには Rust (2024 edition) が必要

## ビルド・実行

```powershell
cargo build --release
.\target\release\ccchattttter.exe
```

終了時に exe と同じディレクトリの `ccchattttter.ini` へ設定を保存する。

インストール・アンインストールはファイルの配置・削除のみで、レジストリは使用しない。

## 使い方

起動すると即座に有効状態でタスクトレイに格納される。

* トレイのダブルクリック、またはメニューの「ウィンドウ表示」で GUI を開く
* ×ボタンは終了ではなくトレイへの再格納。終了はトレイメニューの「終了」から
* 多重起動すると既存インスタンスのウィンドウを呼び出して終了する
* `start` / `stop` ボタンまたはトレイメニューのチェックで抑止を一時停止・再開できる
* ゲームモード用ホットキー（既定 `Ctrl+Alt+G`、ini の `HotKey` で変更）でも開始/停止できる

### ログ

1行の形式は `キー名称、DOWN/UP、経過時間(ms)、判定結果`。

* `DOWN` 時の経過時間:

  * UP監視 OFF → 前回同一キー DOWN から
  * UP監視 ON → 前回同一キー UP から
* `UP` 時の経過時間: 前回同一キー DOWN から
* `clear` ボタンは1回目で押下一覧、空の状態でもう1回押すとチャタ一覧をクリアする
* ログ取得は負荷が高めなので、普段は OFF 推奨（ゲーム中は特に）

## 設定

| 項目                | 既定値  | 意味                                                       |
| ----------------- | ---- | -------------------------------------------------------- |
| DOWN-UP-DOWN (ms) | 50   | 押下時のチャタリング判定間隔。これより短い連続入力をチャタとみなす                        |
| DOWN-DOWN (ms)    | 0    | リピート無視時の連続 DOWN 判定間隔。`0` でリピート中の連続 DOWN を完全無視            |
| UP-DOWN (ms)      | 8    | UP 監視時の判定間隔。DOWN-UP-DOWN より大きくしても意味はない                   |
| チャタキャンセル          | ON   | チャタと判定した入力を捨てる。OFF でも判定自体は行う                             |
| リピート無視            | ON   | `DOWN→DOWN` の連続をチャタとみなさない                                |
| UP監視              | OFF  | UP イベントも表示・判定対象にする                                       |
| ログ                | OFF  | 押下一覧を表示する                                                |
| チャタのみ記録           | OFF  | ログ OFF 時のみ有効。チャタ判定キーのみリストする                              |
| ログ行数              | 1000 | 超えた分は古い方から削除。`0` で無制限（重くなる可能性あり）                         |
| 高精度タイマー           | OFF  | QPC で時間測定する。厳密に見たいとき用                                    |
| テンキー無視            | OFF  | Num0〜9・加減乗除（`NumLock` / `NumEnter` 除外）を判定除外。外付けテンキー誤判定対策 |
| 警告音               | OFF  | チャタ検出時に `sound` セクション指定の wave を再生。ログ無効でも鳴る               |
| 音選択               | —    | 警告音に使う wave ファイルを選ぶ                                      |

### 閾値の決め方

1. ログを表示しながらキーをリピートさせ、連続 DOWN 間隔を確認する
2. それ以下の値を DOWN-DOWN に設定する
3. 環境によってはリピート中に極短時間・同一時刻の連続 DOWN が出る。その場合はリピート無視 ON + DOWN-DOWN `0` にする

チャタのみ記録に何か出ただけでは即チャタと判断しないこと。

瞬間的な CPU 負荷などソフト要因の誤判定もあるため、ログを有効にして該当キーを再確認する。

## オリジナル版について

オリジナルの `ccchattttter` は、キーボードのチャタリングをソフトウェア側で抑止するために作られた Windows 用ツール。

同梱されている `update.txt` によると、初版は **2009年1月24日** に作成され、次の記録が残っている。

```text
◆2009/1/24 初版作成
  お披露目バージョン
   FILCOっていいよな？13ﾁｬﾀ目 560(551)
```

その後も「FILCOっていいよな？」スレッドで寄せられた指摘やアイデアを取り込みながら更新されている。

更新履歴には、たとえば以下の記録がある。

* 13チャタ目 580氏のアイデアを採用
* 13チャタ目 616氏提供のアイコンを採用
* 17チャタ目 >>67、>>101、>>164-165、>>167、>>175 の指摘を反映

このため、FILCO関連スレッドを開発・テスト・フィードバックの場として発展したソフトウェアだったことが分かる。

### オリジナル作者

オリジナル作者の実名、ハンドルネーム、メールアドレス、公式Webサイトなど、作者を確実に特定できる情報は配布物には記載されていない。

これは情報が失われたというより、少なくとも連絡先については作者自身が意図的に公開していなかったと考えられる。

オリジナルの `readme.txt` には次の記述がある。

```text
・連絡は必要ありません。むしろ連絡先は書いておきません。
```

したがって、このリポジトリではオリジナル作者について特定の個人名やハンドルネームを推定せず、単に「オリジナル作者」と表記する。

`readme.txt` に記録されている開発・動作確認環境は以下。

```text
Microsoft WindowsXP Pro SP3
```

配布物には Delphi のソースコードも同梱されており、この Rust 版ではその実装、特に `hooookk.dpr` のキーボードフックおよびチャタリング判定ロジックを参照・移植している。

## 構成

```text
src/
  engine.rs    判定ロジック (hooookk.dpr の移植)
  hook.rs      WH_KEYBOARD_LL フック (startHook/endHook/hookProc 相当)
  ui.rs        メインウィンドウ (Unit1.pas TForm1 相当)
  settings.rs  ccchattttter.ini 読み書き
  tray.rs      タスクトレイ
  hotkey.rs    グローバルホットキー
  keyname.rs   キー名称 table
  win32.rs     Win32 補助

old/           Delphi 版ソース・ドキュメント
               (readme.txt / update.txt / チャタリングについて.txt)
```

判定の詳細（DOWN/UP キャンセル図解）は `old/チャタリングについて.txt`、旧版の履歴は `old/update.txt` を参照。

## 注意・制限

* ウィンドウタイトル別の有効/無効切り替えはできない
* 同時押しは考慮していない
* 一部キー名称は JIS キーボード基準
* キーロガー的動作をする（フック自体が仕組み上そうなる）。気になる場合はソースを確認のうえ、Firewall 遮断などで各自判断すること
